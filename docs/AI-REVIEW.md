## 생성 계약

- 엔진이 등급·역할 슬롯과 UUID를 먼저 정합니다. AI는 해당 슬롯의 이름·성격·관계·외형·허용 스킬을 채웁니다.
- 초기 슬롯은 5성 2명 / 4성 3명 / 3성 3명입니다. 수호·공격·치유·지원 역할을 포함합니다.
- 적은 척후/강타/술사/수호의 엔진 유형 중 하나이며, HP·공격·방어·속도·스킬 수치는 엔진에서 가져옵니다. AI는 설정·속성·도감 ID·이미지 태그를 구성합니다.
- 챕터는 등록된 인물과 적만 참조합니다. 일반 시나리오의 대사 화자는 해당 챕터 배정 인물과 신규 합류 후보만 사용할 수 있습니다.
- 사용자 지침은 모든 단계에 전달됩니다. 이미 확정된 세계 규칙·프로필·저장된 시나리오는 새 배너 때문에 덮어쓰지 않습니다.
- 신규 풀은 캐릭터와 배너가 모두 검증되어야 적용됩니다. 적용 이후 일반 풀에도 추가하고 픽업 배너는 당시 도감 전체를 스냅샷으로 보관합니다.
- 의상 생성은 선정된 보유 캐릭터 ID마다 1개씩만 허용합니다. 얼굴·종족·나이·머리·눈·체형 태그를 의상 태그와 분리하여 재사용합니다.

## 주기 갱신과 비용

- 게임이 켜져 있고 Vertex가 연결되어 있을 때, 주기 갱신 설정을 켠 경우 1분마다 갱신 필요 여부를 확인합니다. 실제 콘텐츠 추가는 7일 주기입니다.
- 전투/독서/설정/지침 편집 중, 모달/생성 중, 숨겨진 탭에서는 갱신하지 않습니다.
- 앱이 꺼져 있는 동안 API를 호출하지 않습니다. 오래 쉬었어도 현재 주기 1개만 생성하며 누락 주기를 모두 소급 생성하지 않습니다.
- 실패한 주기는 매분 유료 재시도하지 않습니다. 소환 화면의 생성 버튼으로 재시도합니다. 실패 체크포인트와 기존 배너를 유지합니다.
- 주기 갱신은 Vertex 텍스트만 생성합니다. NAI 이미지 생성은 사용자가 누른 세계 생성/배너 생성/소환/시나리오 입장/의상 풀 생성 등 실제 게임 조작에서 실행합니다.

## 남은 한계

- 검증기는 ID·역할·스킬·형식·중복을 검사합니다. 자연어 서사의 모든 모순이나 세계 규칙 위반을 의미론적으로 완전히 증명하지는 못합니다.
- NAI의 외형 일관성은 고정 태그와 기존 프로필을 사용해 유지하려는 방식입니다. 다른 의상에서도 얼굴이 완벽히 같다는 보장은 없으며 실계정 이미지 확인이 필요합니다.
- 로컬 싱글 플레이의 기간은 기기 시계를 사용합니다. 서버 시각이나 부정 조작 방지 시스템은 없습니다.
- 실제 API 계정으로 생성한 품질·비용·모델 접근 권한과 실제 PC/모바일 브라우저 화면은 이 작업에서 검증하지 못했습니다. 코드/엔진/모의 응답 테스트 결과와 구분합니다.

## 추가 자체 검토: 인물 이미지

기존 API 요청은 `char_captions`가 빈 배열이어서 고정 외형과 옷·여러 인물의 특징이 공통 프롬프트 하나에 섞였습니다. 이를 12개 고정 외형 항목 + 별도 의상 단계 + 캐릭터 ID별 이미지 설계 + NAI 개별 긍정/부정 칸으로 교체했습니다. 이전 이미지·캐릭터·획득 의상은 보존하고 필요한 프롬프트만 보강합니다. [구현·검증·한계](IMAGE-PROMPTS.md)를 참고하세요.
